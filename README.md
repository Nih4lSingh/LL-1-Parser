# LL(1)-Parser

A beginner-friendly C++ program that reads a context-free grammar, computes FIRST and FOLLOW sets, checks whether the grammar is LL(1), and parses a token sequence when it is.

## Build and run

You need a C++17 compiler such as g++.

On Windows (PowerShell):

```powershell
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o ll1_parser.exe
.\ll1_parser.exe
```

On Linux or macOS:

```sh
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o ll1_parser
./ll1_parser
```

## Entering a grammar

Enter the terminals and nonterminals as space-separated symbols. Then enter the start symbol, the number of production lines, and one production per line. Use `->` between the left and right sides, `|` between alternatives, and `epsilon` for an empty production.

For example, this grammar describes addition and multiplication:

```text
Terminals: id + *
Nonterminals: E Q T R F
Start symbol: E
Number of production lines: 5
E -> T Q
Q -> + T Q | epsilon
T -> F R
R -> * F R | epsilon
F -> id
```

In the running program, type each value at its prompt. The grammar lines above are:

```text
E -> T Q
Q -> + T Q | epsilon
T -> F R
R -> * F R | epsilon
F -> id
```

The program calculates and displays `FIRST` and `FOLLOW` for every nonterminal. It then fills the LL(1) parsing table. If a table cell needs multiple productions, it reports the conflict and says the grammar is not LL(1). If the table has no conflicts, it asks for a string to parse.

## Entering a string

Enter the string as **space-separated terminals**, using the terminal names from your grammar. For the grammar above, enter:

```text
id + id * id
```

The parser prints the production expansions and matches. It accepts the string if the complete input is generated by the grammar; otherwise, it reports a parsing error. Press Enter on an empty line to check the empty string.

## Input rules and current limits

- Every symbol must be listed as a terminal or nonterminal. The two lists must not overlap.
- Use one token per symbol, separated by spaces in the symbol lists, productions, and input string. A multi-character terminal such as `id` is fine.
- `epsilon` is reserved to mean an empty production; write it by itself on the right side.
- The end marker `$` is added by the program. Do not list it as a terminal.
- The program checks LL(1) by detecting conflicts in the generated parsing table. It does not automatically rewrite a grammar that is not LL(1).
